## 文档定位

### 这是什么

本文档是 sel 未来扩展(v2.2 及以后版本)的**候选池**(candidate pool)。

任何"我想在 sel 中加 X" 的想法,都先**入池**而不是直接进入 v2.1 主文档。

入池的候选在**评估窗口**(主要是 Month 6 / 12)被回顾,基于以下三个维度排序:

1. **paper 数据指向性**:是否 paper 数据暴露了需要这个候选填补的空白
2. **实证证据强度**:同行评议文献 + BTC 数据支持
3. **工程价值/成本比**:实施工作量 vs 预期价值

每个评估窗口最多有 1-2 个候选**出池**进入实施。

### 这不是什么

- **不是** "想加什么就立刻能加"的购物车
- **不是** v2.2 设计文档(v2.2 是出池后的形式化)
- **不是** 必须用尽的清单(很多候选可能永远不出池)
- **不是** Claude 单方面的判断列表(Wiki 的入池权和否决权最重要)

### 为什么需要这个文档

防止整合文档 §49.1 警告 1 复发:**工具数量 ≠ 优势**。

人类工程师有一个根深蒂固的认知漏洞:**看到一个工具就想加进系统**。这个漏洞在 AI 辅助下被放大,因为 AI 可以快速生成"这个工具的合理用法"。

整合文档 §49.3 警告 3 "已穷尽错觉" 自承:8 轮调研只覆盖了数学工具的一个切片,8 个未覆盖维度,每个展开都有 10+ 个工具候选。如果 Wiki 想到一个就加一个,sel 三个月就膨胀到 50+ 个 patch。

**候选池的核心机制**:

```
没有候选池:
  Wiki 想到 X → 找 Claude 评估 → "听起来不错" → 改 v2.1 / 进入 v2.2 → 工具栈膨胀

有候选池:
  Wiki 想到 X → 入池(低门槛) → 评估窗口排序(高门槛) → 最多 1-2 个出池
  → 其他候选继续在池中等下次评估
```

### 与 sel 核心纪律的关系

- 整合文档 §35.2:架构层冻结,v2.1 patch 列表冻结
- 整合文档 §47 核心纪律第 1 条:工具不堆砌
- 整合文档 §49.1 警告 1:工具数量 ≠ 优势
- 整合文档 §49.3 警告 3:已穷尽错觉
- 整合文档 §48.9 "突破"定义:6 月节点小突破 / 12 月节点中突破 / 24 月节点真突破

本文档是上述纪律的**操作化工具**——给"想加东西"的冲动一个合法出口,同时保证 paper 期间架构稳定。

## 池的运行规则

### 入池规则(低门槛)

任何来源的候选都欢迎入池:

- Wiki 的"突然想到"
- Claude 的"调研发现"
- paper 数据的"暴露空白"
- 外部论文 / 实战派文章 / 同行讨论

入池只需要填写**最小必要字段**(见下面 Tier 分级)。允许字段不全,只要有候选 ID 和概念草图即可。

### 出池规则(高门槛)

候选**只在评估窗口**(Month 6 / 12 / 24)被考虑出池。

出池条件(必须**全部**满足):

1. **paper 数据出现某个空白**或**现有工具明显不足**
2. **该候选的文献证据强**(同行评议 + BTC 数据)
3. **实施工作量与价值匹配**(不超过 2-3 Wave 的工具优先)
4. **不与现有工具高度重叠**(相关性 < 0.7)
5. **Wiki + Claude 双重 review 通过**
6. **写入 decision_trail**

### 每次评估的出池配额

| 评估窗口 | 出池配额 | 备注 |
|---|---|---|
| Month 3 | 0 | Month 3 不出池,只做现有架构精简(走预注册假设) |
| Month 6 | 最多 1 | 小突破窗口,允许 1 个新工具 |
| Month 12 | 最多 2 | 中突破窗口,允许 2 个新工具或新维度 |
| Month 24 | 最多 3 | 真突破窗口,允许架构层面引入新维度 |

⚠️ 配额是**上限,不是配额**。如果 paper 数据不支持任何出池,**就不出池**。"没数据 → 也不动" 是合法回答。

### 候选 Tier 分级

每个候选被入池时归入 Tier 之一:

| Tier | 含义 | 最小必要字段 |
|---|---|---|
| **A** | 有具体文献基础 + 实施路径清晰 | 来源 / 概念草图 / 候选作用 / 实施工作量估计 / 已知不确定性 / 文献引用 |
| **B** | 8 轮未调研,有领域但无具体文献准备 | 来源 / 概念草图 / 候选作用 / 评估窗口建议 |
| **C** | 浪漫化候选(高度怀疑)或长期方向 | 来源 / 概念草图 / 浪漫化警告 |
| **否决** | 已被严肃讨论后否决 | 否决日期 + 否决理由 + 重新评估时机(如有) |

### 候选在池中的状态变化

```
入池: 任何 Tier(A/B/C)
  ↓
评估窗口被考虑:
  ↓
  ├─ 出池: 进入 v2.x 设计 → 从本文档移除(留下出池记录摘要)
  ├─ 维持: 留在池中,可能 Tier 上升或下降
  ├─ 否决: 转入"已否决"区
  └─ 转长期观察: Tier C 自动转入"长期观察",不进入下次评估
```

### 字段维护规则

| 字段 | 修改规则 |
|---|---|
| 候选 ID | 终身不变 |
| 入池日期 | 不可改 |
| 入池理由 | 不可改 |
| 概念草图 | 可追加(不可删除原版本) |
| Tier | 可变(每次评估窗口可调整) |
| 状态 | 可变 |
| 否决日期 + 理由 | 决策一次后不可改 |

## 前置声明(诚实评估)

缠论无同行评审学术验证,属中文散户技术分析体系。但其部分组件有可检验的学术对应物:
- 背驰 ≈ momentum divergence(弱-中实证)
- 中枢 ≈ congestion zone(中实证)
- 三买 ≈ breakout-retest confirmation(中-强实证,唯一有较强文献支持的组件)

缠论与 sel 的结构同构性(独立发展但切分相似):
```
中枢          ≈ Coiling / Drifting(能量积累区)
趋势          ≈ Surging
背驰          ≈ Exhaustion / Absorption(努力vs结果不匹配,几乎同一概念)
三买          ≈ Release 确认
盘整背驰三种出口 ≈ Critical 多出口(不必然 Cascade)
```

- 级别递归不借(违反 4H 单锚点冻结公理)
- 主观笔段划分不借(违反可机械复现纪律)

## 候选 CHAN-1:Release 回踩确认过滤器

**Tier:B**(有文献支持,待 paper 数据验证)

**概念来源**:缠论"三买"——突破中枢后回踩不回中枢内部,确认突破有效。

**学术对应**:Breakout-retest confirmation。区间突破文献中被反复验证的假突破过滤器。

**sel 映射**:
- 当前 Release 触发 = 价格突破 + OFI 累计跃升 + OI 加速(v2.0 §6.2)
- 新增观察量:Release 触发后 N 个 4H bar 内的回踩行为

**observation-only 定义**:
```
Release 事件触发后,跟踪后续 6 个 4H bar(24 小时):
  retest_low = 触发后 6 bar 内最低价(做多方向;做空镜像)
  coiling_upper = 触发前 Coiling/Drifting-Charged 区间上沿

分类:
  A 类 Release(强确认):retest_low > coiling_upper(回踩不入区间)
  B 类 Release(弱确认):retest_low 进入区间但未触区间中点
  C 类 Release(失败候选):retest_low 跌破区间中点

记录字段(写入 v2_inverse_vocab_events,vocab_type='chan_retest'):
  release_id / 触发时间 / 分类 / retest_low / coiling_upper / 后续 24H 收益
```

**可证伪假设**:
- H-CHAN1:A 类 Release 后续 24H 同向收益显著高于 C 类(t-test p < 0.10)
- 失败标准:A/C 两类无显著差异 → 回踩确认在 BTC 4H 上无价值,废弃

**Month 3 评估问题**:paper 期间 Release 样本预计 5-15 次,样本可能不足。若不足,推至 Month 6 评估。

**若通过**:v2.2 升级路径 = 策略 1 入场决策树 Step 后追加"回踩确认加权"(不是硬性 veto,是置信度系数)。

**工程量**:0.5 Wave(observation 记录逻辑 + 评估脚本)。

## 候选 CHAN-2:背驰量化作为 Exhaustion 平行检测器

**Tier:C**(概念有对应物但实证弱,纯对照实验)

**概念来源**:缠论"背驰"——价格新高/新低但走势段的动量(MACD 面积)衰减。

**学术对应**:Momentum divergence。单独使用胜率接近随机;作为趋势衰竭的确认信号有弱-中正面证据。

**sel 映射**:
- 当前 Exhaustion 触发 = OFI 衰减 + σ 见顶 + OI 增速放缓(v2.0 §6.2)
- 背驰提供一个不同角度的衰竭代理:动量面积比较

**observation-only 定义**:
```
Surging 状态期间,每个 4H bar 计算:
  当前走势段动量 = Surging 进入以来的 |累计收益| / bar 数
  前一同向走势段动量 = 上一次同向 Surging 的同指标(若存在)

背驰候选:价格创出前段极值,但当前段动量 < 前段动量 × 0.7

记录字段(vocab_type='chan_divergence'):
  时间 / 当前动量 / 前段动量 / 比值 / 后续 Exhaustion 是否在 3 bar 内发生
```

**可证伪假设**:
- H-CHAN2:背驰候选出现后 3 个 4H bar 内 Exhaustion 触发的概率显著高于无背驰的 Surging bar(基线对照)
- 失败标准:lead 无显著性 → 背驰不比 sel 现有 Exhaustion 检测更早,废弃

**Month 3 评估问题**:Surging 样本依赖市场状态,可能稀少。

**若通过**:不升级为主决策,升级为 Exhaustion 的辅助 log(类似 AR1 的地位)。

**工程量**:0.5 Wave。

## 候选 CHAN-3:中枢重叠度作为 Coiling 辅助特征

**Tier:C**(几何视角补充,最低优先级)

**概念来源**:缠论"中枢"——连续三段走势的价格重叠区间。

**学术对应**:Congestion zone / consolidation range。区间识别本身无争议,争议在预测力。

**sel 映射**:
- 当前 Coiling 判定 = σ 30 分位以下 + 熵 30 分位以下 + OI 累计正 + funding 非极端(v2.0 §5.2)
- 中枢重叠度提供纯几何角度:近 N 段 swing 的价格区间交集宽度

**observation-only 定义**:
```
每个 4H bar 计算:
  用 zigzag(阈值 = 1.5 × ATR)切分最近 9 段 swing
  取最近 3 段的价格区间交集:
    overlap_width = max(0, min(highs) - max(lows))
    overlap_ratio = overlap_width / ATR

记录字段(vocab_type='chan_pivot'):
  时间 / overlap_ratio / 当前 sel 状态 / 是否 Coiling
```

**可证伪假设**:
- H-CHAN3a:overlap_ratio 高分位(>70)与 sel Coiling 判定的重合率 > 60%(收敛性验证)
- H-CHAN3b:overlap_ratio 高但 sel 非 Coiling 的 bar,后续行为更接近 Coiling 还是当前标注状态?(分歧样本价值验证)
- 失败标准:H-CHAN3a < 40% 且 H-CHAN3b 无信息量 → 几何视角与统计视角完全不重合且无互补,废弃

**价值定位**:这个候选的真实价值不是替代 Coiling 判定,而是**校验** sel 的 Coiling 定义是否遗漏了几何上明显的盘整结构。

**工程量**:0.5-1 Wave(zigzag 实现 + 记录)。

## 候选 ICT-1:VPIN(Volume-Synchronized Probability of Informed Trading)

**Tier:B+**(本批最高优先级——同行评审支持最强的"聪明钱"可观测量)

**概念来源**:ICT"机构建仓留下足迹"叙事的学术对应物。Easley-López de Prado-O'Hara 框架。

**2024-2026 文献支持**:
- Kitvanitphasu et al. 2025:VPIN 与 BTC 价格跳跃(discontinuous price movements)显著相关
- Easley et al. 2024:VPIN 类指标(与 Roll's measure 等流动性代理并列)对主要加密货币市场动态有实质解释与预测力
- 传统市场:Easley et al. 2012 VPIN 预测极端价格运动(Flash Crash 前兆检测的经典文献)

**与 sel 现有量的区别**:
- OFI/TF:看**方向**(买卖净额)
- VPIN:看**毒性**(以成交量桶同步的买卖不对称持续性,方向无关)
- 两者互补:高 VPIN + OFI 方向 = 知情交易者正在单边建仓的证据链

**observation-only 定义**:
```
VPIN 计算(从 v2_ticks,标准 Easley 流程):
  1. 成交量桶:V_bucket = 30 天日均成交量 / 50(自适应桶大小)
  2. 每桶内:用 bulk volume classification(BVC)或 tick rule 分类买/卖量
  3. VPIN_t = 最近 50 桶的 Σ|V_buy - V_sell| / Σ V_total
  4. 记录 VPIN 滚动 90/95/97 分位

写入 v2_inverse_vocab_events(vocab_type='vpin'):
  时间 / VPIN 值 / 当前分位 / 当前 sel 状态
```

**可证伪假设**:
- H-ICT1a:VPIN > 95 分位的时刻,后续 24H 出现 |收益| > 2σ 事件的概率显著高于基线(跳跃预测,复现 Kitvanitphasu 2025 在 sel 数据上)
- H-ICT1b:Critical 状态 + VPIN > 95 分位 → Cascade 转化率显著高于 Critical + VPIN 正常(状态机增强价值)
- 失败标准:两者都不显著 → VPIN 在 4H 决策尺度上无增量信息,废弃

**若通过**:v2.2 升级路径两条(择一):
- (a) Critical 主条件家族追加候选(需与 H2/TDA1 做冗余性检验,遵守"最多 4 个主条件"纪律)
- (b) 策略 2 Step 4 cascade 风险过滤的增强因子

**工程量**:1 Wave(BVC 分类 + 桶化 + 滚动分位;v2_ticks 数据已就绪)。

**注意事项**:OKX 属 Cong et al. 2023 分类中的相对合规组,但 VPIN 对刷单敏感——若未来接入其他交易所数据,必须先做 wash trading 过滤。
