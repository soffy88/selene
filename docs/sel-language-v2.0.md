# 第一部分:语言基础与公理

## 1. 文档定位与生效边界

### 1.1 sel 是什么

sel 是 **Selene 项目用于"为 BTC 市场行为命名"的有限词汇集合**。它不是预测算法,不是交易策略,也不是技术指标系统。它是一套 **状态语言**:

- 输入:BTC 的 tick / LOB / 衍生品 / 链上多源数据
- 输出:在每个 4H 时间锚点产生一个"市场状态名"
- 用途:状态名作为策略 1 的方向过滤器,CUSUM 事件作为策略 2 的入场触发

sel 与 Helixa 的根本区别:

| 维度 | Helixa | Selene(用 sel) |
|---|---|---|
| 视角 | LLM + 多因子打分 | 状态机 + 物理类比 |
| 决策粒度 | 分数高低 | 状态分类 |
| 时间尺度 | 多尺度(已实施) | 4H 主 + CUSUM 事件 |
| 工具栈 | nautilus-trader | 自研 execution + TimescaleDB |
| 哲学 | "市场可被打分" | "市场处于某状态" |

### 1.2 sel 生效的边界

sel 仅在以下范围内有意义:

- ✅ BTC 市场(BTC/USDT,主交易场所 OKX,辅助参考其他主流交易所)
- ✅ 4H 主时间锚点 + CUSUM 事件流
- ✅ paper trading 阶段及随后的小资金实盘验证
- ❌ **不**适用 BTC 以外资产(ETH/SOL 等需重新验证 sel 假设)
- ❌ **不**适用低于 sub-minute 的高频(Hawkes / OFI 不能直接用 sel 状态)
- ❌ **不**适用日线以上的宏观周期(Wyckoff 阶段虽用 4H 但不向上延伸到周线)

### 1.3 sel 的可证伪性立场

sel 是**可证伪的研究框架**,不是"我相信它管用"的信仰系统。本文档第七部分会给出每条假设的可证伪条件。当 paper trading 数据与假设冲突时:

1. 优先承认假设失败
2. 将相关词汇降级为 observation-only(只记录不决策)
3. 不通过添加新规则"救活"已被证伪的假设

⚠️ 这是 sel 设计纪律的核心。

## 2. 五条公理

### 公理 1:市场是耗散系统

**陈述**:BTC 市场不是 EMH 假设的均衡系统,而是远离均衡的耗散结构。能量(资金、信息、参与者注意力)持续流入,系统通过价格波动、流动性消耗、信息扩散等方式持续耗散能量。

**对 sel 的影响**:
- 状态识别可行(系统有可识别的稳定子结构)
- 状态可转换(能量积累/释放驱动转换)
- 永远不会"达到平衡"(EMH 只是局部近似)

**支持文献**:Mandelbrot (1963), Lo (Adaptive Markets, 2017), Begusic et al. 2018(BTC SOC 实证)

### 公理 2:价格是过程的签名,不是过程本身

**陈述**:价格 K 线是市场博弈过程的低维投影,不能反向重构出完整过程。但价格签名(配合订单流、衍生品、链上等多源数据)足以推断当前所处的状态类型。

**对 sel 的影响**:
- 单看价格 K 线不足以识别状态(必须叠加 LOB / 衍生品 / 链上)
- 价格反推(reverse inference)是 sel 反推词汇的合法路径
- 但"看图猜状态"不可靠,必须有量化证据

### 公理 3:观察具有层级性

**陈述**:不同信号在不同时间尺度上才能被有效观察:

- **微观层(秒~分钟)**:OFI / Hawkes / 跨所价差 / 即时流动性
- **中频层(15min~4H)**:状态识别 / Cascade 过程 / 衍生品累积
- **宏观层(日~周)**:Wyckoff 阶段 / 趋势级别 / ETF 流入

**对 sel 的影响**:
- sel 必须是多尺度架构,不是单一时间锚点
- 但**决策必须在某一固定锚点进行**(否则无法回测、无法纪律化)
- v2.0 的选择:**4H 决策锚点 + CUSUM 事件触发**

### 公理 4:状态先于事件,但事件改变状态

**陈述**:状态(Coiling / Surging / Drifting / Critical / Cascade)有内在持续性,不会逐 bar 切换。但极端事件(Cascade 触发、Critical 突变)会立即重置状态。

**对 sel 的影响**:
- 状态机有最小持续时间约束(防止抖动)
- 但保留"红线事件即时重置"的逃生通道
- v2.0 的实施:**最小停留 = 状态特定值**(在第 5 节定义)

### 公理 5:可证伪 > 解释力

**陈述**:sel 优先选择可被实证数据证伪的假设,不优先选择"听起来合理"或"能解释一切"的假设。

**对 sel 的影响**:
- Wyckoff 派生词汇在 BTC 文献空白,只能 observation-only
- AR1-as-Critical-trigger 已被 Tu 2020 BTC 数据证伪,降级为辅助
- 任何新词汇加入必须先列出可证伪条件

## 3. 核心抽象:市场作为耗散系统

### 3.1 三个守恒量类比

物理耗散系统有几个守恒量,在 BTC 市场有对应类比(类比仅供直觉,不作为量化依据):

| 物理 | BTC 市场近似 | 可观测代理 |
|---|---|---|
| 能量 | 流入 BTC 的资金 + 注意力 | OI 增量 / 链上转账 / 社交媒体提及 |
| 熵 | 信息分布的不确定性 | LOB Shannon 熵 / 价格分布偏度 |
| 物质 | BTC 总量 | 交易所余额变化 / 链上活跃地址 |

⚠️ **类比的边界**:这些不是真守恒量,只是"在某段时间内变化缓慢"的量。不要在数学层面套用物理公式。

### 3.2 SOC(自组织临界)的真实角色

BTC 表现出 SOC 特征的实证证据(强):

- **重尾分布**(Begusic 2018):BTC 收益分布的 power-law 尾部参数 α ≈ 2.5-3.5
- **Cascade 自激发**(Turiel & Aste 2021):流动性枯竭引发的清算瀑布在 BTC 上有明确实证
- **多分形结构**(Pontiggia 2025):BTC 高频波动率呈多分形,大波动主导

**对 sel 的影响**:
- Cascade 是真实的物理现象,不是"市场情绪"
- Cascade 的早期预警(流动性枯竭信号)在 sel 中有专门词汇(见第 5 节)
- Cascade 触发后的"reset 机制"对应 SOC 的能量重置

### 3.3 临界相变的真实角色(v1.1 修订后)

v1.0 设计中,Critical 状态以 AR1(自相关上升)为主条件。v1.1 修订(基于 Tu 2020 实证):

- **Tu 2020(arxiv 1806.08386)在 BTC daily 数据上证明 AR1 不能预警 Critical**
- 但 σ(滚动标准差)的单调上升仍有效

v2.0 继承 v1.1 修订:**Critical 状态以 σ-based 为主,AR1 仅作为辅助 log 不参与决策**。

## 4. 词汇表概览

sel v2.0 词汇分三类:

```
状态词汇(6 个)— 描述市场当前所处的稳定结构
  Coiling          (盘整 / 蓄能)
  Surging          (突破 / 释放)
  Drifting-Calm    (平静漂移)
  Drifting-Charged (带电漂移)
  Critical         (临界 / 警戒)
  Cascade          (瀑布 / 系统性事件)

转换词汇(7 个)— 描述状态间的合法转换
  Release          (Coiling → Surging)
  Exhaustion       (Surging → Drifting/Critical)
  Decay            (Drifting-Charged → Drifting-Calm)
  Charging         (Drifting-Calm → Drifting-Charged 或 Coiling)
  Stress           (Drifting/Coiling → Critical)
  Trigger          (Critical → Cascade)
  Reset            (Cascade → Drifting-Calm)

反推词汇(7 个)— 从局部 PA/ICT 现象向上抽象的子机制
  Absorption       (努力 vs 结果不匹配)
  Imprinting       (做市商订单印迹,弱实证)
  Sweep            (流动性扫荡)
  Crowding         (拥挤交易)
  Divergence       (跨所价差异常)
  Dislocation      (流动性位错)
  Saturation       (饱和压力)
```

完整定义见第二部分。

# 第二部分:状态机与反推词汇

## 5. 状态词汇(6 状态完整定义)

### 5.1 状态判定的统一约定

- **判定锚点**:每个 4H bar 收盘后判定下一阶段状态
- **判定输入**:该 4H bar 内 16 个 15min 子聚合特征 + 衍生品累积变化 + 链上事件
- **最小停留时间**:每个状态有特定值(防抖动,见各状态定义)
- **红线即时切换**:Cascade 触发时立即切换,不等最小停留

### 5.2 Coiling(盘整 / 蓄能)

**直观语义**:市场处于"装弹"阶段,价格在窄区间内振荡,流动性逐步累积,衍生品 OI 缓慢增长,但尚未爆发。

**进入条件**(全部满足):
- 4H 价格 σ 进入过去 30 天的 30 分位以下(波动收敛)
- LOB Shannon 熵进入过去 30 天的 30 分位以下(订单密度集中)
- OI 累计变化率 > 0(资金缓慢累积)
- funding rate 不在极端(|funding| < 80 分位)

**离开条件**:
- → Surging:Release 触发(见第 6 节)
- → Critical:Stress 触发
- → Drifting-Charged:Charging 触发(蓄能但未爆发)

**最小停留**:6 个 4H bar(24 小时)— 防止 1-2 个 4H 的假收敛被识别为 Coiling

**典型可观测信号**:
- 15min 聚合的 OFI 方差降低
- 跨所价差(Divergence)收敛
- 链上活跃地址略增但巨鲸不动

**v2.0 在策略中的角色**:
- 策略 1:Coiling 是"准备入场"信号,等 Release 转换确认方向
- 策略 2:Coiling 期间 CUSUM 阈值通常未达,自然不会触发短线

### 5.3 Surging(突破 / 释放)

**直观语义**:盘整后的方向爆发,价格快速移动,衍生品 OI 加速,流动性被消耗。

**进入条件**(从 Coiling 经 Release 转换):
- 价格突破前 24 小时 high(或 low)
- 4H 价格 σ 跃升至过去 30 天 70 分位以上
- 同向 OFI 累计在 12 小时内达过去 7 天 90 分位
- OI 加速增长

**或**(从 Drifting-Charged 经 Release):
- 类似条件,但触发更宽松(因为已蓄能)

**离开条件**:
- → Drifting-Calm/Charged:Exhaustion 触发(动能耗尽)
- → Critical:Stress 触发(风险上升)
- → Cascade:Trigger 触发(罕见,通常 Surging → Critical → Cascade 中转)

**最小停留**:2 个 4H bar(8 小时)— 防止单次突破被立即误判为 Surging 退出

**v2.0 在策略中的角色**:
- 策略 1:**Surging = 持仓中状态**,继续持有,等 CUSUM 反向触发或退出 Surging
- 策略 2:Surging 期间频繁出现 CUSUM 短频触发,但需衍生品过滤

### 5.4 Drifting-Calm(平静漂移)

**直观语义**:无明显方向,流动性正常,无能量累积也无消耗,市场处于"无聊"状态。

**进入条件**:
- 4H 价格 σ 在过去 30 天的 30-60 分位
- LOB 熵在 40-70 分位(中等不确定性)
- OI 变化率近零
- 无明显方向性 OFI

**离开条件**:
- → Coiling:σ 和熵同步降到 30 分位下(能量收敛)
- → Drifting-Charged:Charging 触发(开始蓄能)
- → Surging:罕见,通常需经 Coiling

**最小停留**:8 个 4H bar(32 小时)

**v2.0 在策略中的角色**:
- 策略 1:**完全不入场**,Drifting-Calm 不产生方向信号
- 策略 2:CUSUM 短频可能仍触发(噪声反转交易),但需更严格的衍生品过滤

### 5.5 Drifting-Charged(带电漂移)

**直观语义**:无明显方向但已开始蓄能,衍生品 OI 显著增长,price action 紧张但未突破。是 Coiling 和 Surging 之间的中间态。

**进入条件**:
- 类似 Drifting-Calm 的方向不明
- **但** OI 累计增长率 > 过去 30 天 70 分位
- **或** funding rate 持续偏向某方向(连续 24h 同号)

**离开条件**:
- → Coiling:能量收敛(σ 进一步下降)
- → Surging:Release 触发(直接爆发)
- → Critical:Stress 触发

**最小停留**:4 个 4H bar(16 小时)

**v2.0 在策略中的角色**:
- 策略 1:**准备入场**,等 Release(类似 Coiling 但路径更短)
- 策略 2:CUSUM 短频可能频繁触发,反推词汇(尤其 Crowding)增强信号

### 5.6 Critical(临界 / 警戒)

**直观语义**:系统接近相变点,小扰动可能引发大事件。但 Critical 不必然导致 Cascade —— 也可能"软着陆"回 Drifting。

**进入条件**(σ-based,v1.1 修订后):
- 4H 价格 σ 进入过去 30 天 90 分位以上
- σ 在过去 12 小时单调上升
- 熵的变化率方差上升(系统不稳定)
- **可选辅助 log**:AR1 上升(只记录,不参与决策)

**离开条件**:
- → Cascade:Trigger 触发(σ 突破 97 分位 + 流动性枯竭)
- → Drifting:Decay(危机解除)
- → Surging:罕见,需明显方向性

**最小停留**:1 个 4H bar(4 小时)— 临界态本就不稳定,允许快速切换

**v2.0 在策略中的角色**:
- 策略 1:**进入 Critical 时减仓 50%**(继承 v1.1 折衷决策),不新开仓
- 策略 2:**暂停新开仓**,已有仓位收紧止损

### 5.7 Cascade(瀑布 / 系统性事件)

**直观语义**:SOC 触发,清算瀑布或单向流动性枯竭,价格快速大幅移动,无法正常交易。

**进入条件**(任一即触发,即时切换):
- 4H 价格 σ > 过去 30 天 97 分位 + 流动性枯竭(LOB 深度跌至 7 天 5 分位)
- liquidation 脉冲超过过去 30 天均值的 5 倍
- 跨所价差(Divergence)持续 > 0.5% 超过 5 分钟

**离开条件**:
- → Drifting-Calm:Reset(系统重置,通常 4-12 小时后)

**最小停留**:无下限(cascade 可短可长,数据决定)

**v2.0 在策略中的角色**:
- 策略 1 + 策略 2:**红线 — 立即清仓所有持仓**(各自子账户独立清仓)
- Cascade 期间不新开仓,等 Reset

### 5.8 状态判定优先级

当多个状态条件同时满足时,按以下优先级判定:

```
Cascade > Critical > Surging > Coiling > Drifting-Charged > Drifting-Calm
```

理由:风险事件优先识别。

```
              ▼   │                            │           │
     ┌──────────────────────┐                  │           │
     │   Drifting-Charged   │                  │           │
     └──────────────────────┘ ──── Stress ──► Critical     │
              │                                ▲           │
        Charging(继续蓄能)                     │           │
              │                                │ Stress    │
              ▼                                │           │
     ┌──────────────────────┐                  │           │
     │      Coiling         │ ──── Stress ────┘           │
     └──────────────────────┘                              │
              │                                            │
        Release                                            │
              │                                            │
              ▼                                            │
     ┌──────────────────────┐                              │
     │      Surging         │ ──── Exhaustion ────────────┘
     └──────────────────────┘
```

### 6.2 七个转换词汇定义

#### Release(Coiling → Surging 或 Drifting-Charged → Surging)
- 触发:价格突破 + OFI 累计跃升 + OI 加速
- 方向:由突破方向决定
- 反推词汇配合:常伴随 Sweep(突破前扫荡止损)

#### Exhaustion(Surging → Drifting)
- 触发:OFI 衰减 + σ 见顶 + 衍生品 OI 增速放缓
- 反推词汇配合:常伴随 Absorption(努力大但价格不动)

#### Decay(Drifting-Charged → Drifting-Calm)
- 触发:OI 增速放缓 + funding 回归中性
- 慢速过程,通常持续多个 4H

#### Charging(Drifting-Calm → Drifting-Charged 或 Drifting → Coiling)
- 触发:OI 加速增长 + σ 收敛 + 流动性增加
- 慢速过程

#### Stress(Drifting/Coiling → Critical)
- 触发:σ 跃升至 90 分位 + 熵不稳定
- 快速过程,通常 1-2 个 4H

#### Trigger(Critical → Cascade)
- 触发:σ > 97 分位 + 流动性 < 5 分位 + liquidation 脉冲
- 即时,毫秒级判定

#### Reset(Cascade → Drifting-Calm)
- 触发:流动性恢复 + σ 衰减 + OI 大幅下降
- 通常 4-12 小时

## 7. 反推词汇(7 个)

反推词汇是从 PA/ICT/Wyckoff 等局部现象**向上抽象**的子机制描述。它们**不是状态**,而是状态中可以叠加的修饰。

⚠️ **角色重定位**:v1.0/v1.1 中反推词汇主要服务状态判定。v2.0 中反推词汇**主要服务策略 2**(日内短线 CUSUM 触发的增强),对策略 1(4H 趋势)用处较小。

### 7.1 Absorption(吸收)

**定义**:大量买卖努力(volume / OFI)被对手方吸收,价格几乎不动。表明强势对手挂单或做市商干预。

**可观测**:
- 高成交量 + 低价格变动
- 高 OFI + 价格不跟随
- LOB 一侧深度持续被吃但维持

**v2.0 角色**:
- 策略 2:CUSUM 信号 + Absorption 出现 = 增强反向信号(动能被吃)
- 策略 1:观察辅助,不直接进入入场决策

**实证支持**:Kyle's lambda 框架(强)+ BTC OFI 文献(中)

### 7.2 Imprinting(印迹)

**定义**:做市商或大户的订单印迹,表现为重复出现的、非自然的 LOB 模式。

⚠️ **实证薄弱**:在 BTC 上无大规模学术验证,主要来自交易员经验。

**v2.0 角色**:
- observation-only,只记录不参与决策
- paper trading 收集数据,3 个月后评估是否有可量化模式

### 7.3 Sweep(流动性扫荡)

**定义**:快速大单扫除一侧的止损/挂单,通常发生在突破前(诱多/诱空)或突破时。

**可观测**:
- 单一 tick 跨多个价格档位
- 同方向 OFI 在数秒内极端聚集
- 跨所价差(Divergence)瞬时扩大后收敛

**v2.0 角色**:
- 策略 2:Sweep + CUSUM 反转 = 强反转信号(经典假突破真反转)
- 策略 1:Sweep 在 Coiling/Drifting-Charged 期间出现 → 即将 Release 的信号

**实证支持**:Bishop et al. 2022 跨所价格领先研究(强)

### 7.4 Crowding(拥挤)

**定义**:衍生品市场单方向头寸过度集中,形成"挤兑"风险。

**可观测**:
- funding rate 持续极端(|funding| > 90 分位)
- OI 高位 + funding 高位 + 多空比极端
- 历史类似配置后多次出现 cascade

**v2.0 角色**:
- 策略 1:Crowding + Surging 同向 = 入场风险高,降仓位 50%
- 策略 2:Crowding + CUSUM 反转 = 强反转信号

⚠️ **post-ETF 警告**(v2.0 新增):2024+ Ethena 等基差套利协议扭曲了 funding rate,Crowding 的"散户拥挤"解释失效。需要在 sel 中显式标注"funding 来源未知时,Crowding 信号降级"。

**实证支持**:XT 2026 cycle 分析(中)+ 2025-11 cascade 事件(强,但样本少)

### 7.5 Divergence(跨所价差异常)

**定义**:不同交易所的 BTC 价格出现异常价差,反映流动性碎片化或大额套利失效。

**可观测**:
- OKX vs Binance vs Coinbase 的价差超过 0.1%
- 价差持续时间超过 5 秒(超过套利者套利窗口)
- 价差扩大方向通常领先大趋势

**v2.0 角色**:
- 策略 1 + 策略 2:Divergence 出现 → Cascade 风险预警,仓位收紧
- v1.0 中此词汇被埋没为辅助,v2.0 提升为独立信号

**实证支持**:Bishop et al. 2022(强,500ms 尺度)

### 7.6 Dislocation(流动性位错)

**定义**:LOB 深度在某一侧出现异常缺失,但价格未立即反应。预示该方向的"撑不住"。

**可观测**:
- LOB 一侧深度跌至 7 天 10 分位以下
- 但价格未明显移动(尚未触发 cascade)

**v2.0 角色**:
- 状态机辅助:Dislocation + Critical = Cascade 高概率
- 策略 1:看到 Dislocation 时退出方向交易

**实证支持**:Cont 2010 LOB 框架(强)+ BTC LOB 实证(中)

### 7.7 Saturation(饱和压力)

**定义**:某状态持续时间超过历史典型时长,表明系统处于"高压锅"状态,转换概率上升。

**可观测**:
- Coiling 持续 > 7 天(历史中位数 3 天)
- Drifting-Charged 持续 > 5 天(历史中位数 2 天)

**v2.0 角色**:
- 状态机辅助:Saturation 提示"准备转换"
- 策略 1:Saturation + Coiling = 入场信号优先级提升

**实证支持**:经验观察(弱),paper trading 收集数据验证

## 8. 词汇语法关系

### 8.1 状态-反推词汇组合

每个状态下,某些反推词汇有特定的"加权效应":

| 状态 | 强增强词汇 | 强反向词汇 |
|---|---|---|
| Coiling | Saturation, Charging | Dislocation |
| Surging | Sweep, Release | Absorption |
| Drifting-Calm | (无) | Saturation, Crowding |
| Drifting-Charged | Crowding, Saturation | Dislocation |
| Critical | Dislocation, Crowding | Decay |
| Cascade | (无,自身定义) | (无) |

### 8.2 反推词汇的多重出现

- 一个 4H bar 内可同时出现多个反推词汇(Sweep + Crowding 等)
- 多重出现时,信号增强(策略 1/2 的入场置信度提升)
- 但**最多取 3 个相关反推词汇**(避免过拟合到罕见组合)

## 9. 物理学底座

### 9.1 SOC 与 Cascade 的对应

**自组织临界(SOC)理论核心**:开放系统在能量持续输入下,自然演化到临界状态,此时小扰动可引发任意大小的雪崩。

**对 sel 的对应**:
- BTC 持续接受资金流入 + 衍生品杠杆累积 = 能量输入
- Coiling/Drifting-Charged = 能量积累阶段
- Critical = 临界状态
- Cascade = 雪崩
- Reset = 系统重置回低能态

**实证强度**:Begusic 2018 / Turiel 2021 直接证明 BTC 上的 SOC 特征(强)

### 9.2 临界相变与 σ-based 预警

**临界相变理论**:系统接近相变点时,涨落幅度上升、相关时间延长、空间相关增强。

**对 sel 的对应**:
- σ 上升 = 涨落幅度上升 ✅(实证支持)
- AR1 上升 = 相关时间延长 ⚠️(Tu 2020 在 BTC 上证伪)
- 跨变量相关增强 = 空间相关 ✅(Divergence 词汇捕获)

**v1.1 修订**(继承到 v2.0):AR1 降级为 log,σ 为主条件。

### 9.3 渗流与流动性枯竭

**渗流理论**:系统中可流通的"路径"被阻塞到一定比例时,整体流通性突然崩溃。

**对 sel 的对应**:
- LOB 深度 = 流通路径
- 流动性枯竭 = 渗流失败
- Cascade = 渗流相变后的崩溃

**实证强度**:Turiel & Aste 2021 直接证明 BTC flash crash 是渗流相变(强)

# 第三部分:时间架构(v2.0 重构)

## 10. 4H 主时间锚点

### 10.1 为什么是 4H

v2.0 调研(2026-04-29)的关键文献证据:

**Bieganowski & Slepaczuk 2026(arxiv 2602.00776)**明确指出 BTC 不同时间尺度的预测能力:
- **< 60 min**:LOB 微观结构主导,可预测性强
- **60-300 min**:噪声敏感区,信噪比最差
- **12-24 h**:不确定性主导,预测衰退
- 4H = 240 min,在噪声敏感区**末尾**,信噪比开始改善

**HMM regime detection 主流文献**(Machimbo 2025 / TVTP-MS-HAR 2025):
- 主流尺度是 **4H 和 daily**
- 1H 和 hourly 应用较少且效果较差

**Wyckoff 阶段在 BTC 上的天然尺度**:
- Wyckoff Analytics / Altrady 2025 实证:**4H 是 Wyckoff 阶段的最佳观察尺度**
- 1H 切碎阶段,daily 错过转折

**funding rate 周期对齐**:
- OKX funding 8H 结算
- 4H = 半个 funding 周期,可观察 funding 演化的中点

### 10.2 4H 的代价

诚实标注:

⚠️ **数据量减少**:1 年 BTC 数据
- 1H bar:8760 个
- 4H bar:**2190 个**
- 减少 4 倍

⚠️ **OOS 验证更难**:
- 6 个月 OOS = 1095 个 4H bar
- 状态切换事件可能只有 50-100 次,部分状态样本严重不足
- Cascade 一年估计 < 30 次,任何针对 Cascade 后续的统计推断不稳

⚠️ **决策时机延迟**:
- 4H 决策意味着最坏情况下决策延迟 4 小时
- 但这被 CUSUM 事件流弥补(见第 11 节)

### 10.3 4H 的最终选择理由

按公理 5(可证伪 > 解释力):
- 4H 有最强文献证据(HMM 主流 + Wyckoff 天然尺度 + 噪声区出口)
- 1H 在文献中明确指出是噪声敏感区
- 数据量减少是真实代价,但**信号质量提升 > 样本量减少**

## 11. CUSUM 事件流的双套参数

### 11.1 为什么需要 CUSUM 补充 4H

4H 主时间锚点解决"状态识别"问题,但有两个空白:

1. **入场时机精度不够**:4H 锚点意味着至多 4 小时延迟入场,可能错过最佳入场点
2. **微观信号被丢失**:OFI / Hawkes / 跨所价差等 sub-minute 信号在 4H 下被平均掉

**CUSUM event-driven** 填补这两个空白(参见 Lopez de Prado 2018 + Alexdemachev 2026 BTC 实证)。

### 11.2 CUSUM 数学骨架

按经典 Page CUSUM(1954):

```
z_t = (r_t - μ_t) / σ_t        # 标准化收益(只用过去数据)
C+_t = max(0, C+_{t-1} + (z_t - k))    # 上行累积器
C-_t = min(0, C-_{t-1} + (z_t + k))    # 下行累积器

触发:
  上行事件:C+_t > h_t
  下行事件:|C-_t| > h_t

重置:触发后 C 清零

参数:
  k = drift 参数(过滤小噪声),典型 = 0.5σ
  h_t = 阈值,通常用滚动分位数估计(因果)
```

### 11.3 双套参数设计

策略 1 和策略 2 的 CUSUM **共享底层 z-returns 计算**(同一份 tick 数据),但**阈值参数不同**:

#### 策略 1:CUSUM-Mid(中频)

```
累积窗口:30min ~ 2h
- 计算:μ_t / σ_t 用过去 2h 滚动估计
- z_t 在 1min tick 聚合上计算

阈值 h:30 天滚动 90 分位
- 即过去 30 天中,Page CUSUM peak 值的 90 分位
- 较高阈值 = 较少触发 = 适合中频趋势策略

drift k:0.5σ(经典推荐)
```

**预期触发频率**:策略 1 一年触发 100-300 次(估计,待 OOS 标定)

#### 策略 2:CUSUM-Short(短频)

```
累积窗口:30s ~ 10min
- 计算:μ_t / σ_t 用过去 10min 滚动估计
- z_t 在 1sec tick 聚合上计算

阈值 h:7 天滚动 95 分位
- 较短期 + 更高分位 = 频繁触发但需高确信度

drift k:0.5σ
```

**预期触发频率**:策略 2 一年触发 1000-3000 次(估计,待 OOS 标定)

### 11.4 CUSUM 占位符警告

⚠️ 上述所有数值(累积窗口、阈值分位数、drift k)是**占位符**,需 OOS 标定。Wiki 不应在 paper trading 启动前根据直觉调整这些值。**第一次有效调参应等到 paper 跑 1 个月后**,基于真实触发频率反馈。

### 11.5 CUSUM 与状态机的耦合

```
策略 1(4H 趋势)入场决策:
  Step 1: 4H 状态判定 → 必须是 Coiling 或 Drifting-Charged
  Step 2: CUSUM-Mid 触发 → 判定方向
  Step 3: 衍生品过滤 + 链上过滤
  Step 4: 通过 → 入场

策略 2(日内短线)入场决策:
  Step 1: CUSUM-Short 触发 → 判定方向
  Step 2: 反推词汇增强(Sweep/Absorption/Crowding)
  Step 3: 衍生品过滤(避开 cascade 中)
  Step 4: 状态机过滤 — 仅检查是否处于 Cascade(若是则不入场)
  Step 5: 通过 → 入场
```

**关键差异**:
- 策略 1:状态机优先,CUSUM 触发时机
- 策略 2:CUSUM 优先,状态机仅 veto Cascade

  - 大额充值持续 → Critical 风险上升(可能抛售)
  - 策略 2:不直接使用(链上延迟太高)

# 第四部分:双策略架构

## 13. 策略 1:4H 趋势跟随

### 13.1 策略 1 定位

策略 1 是 sel 项目的**主策略**,目标是捕获 BTC 的中频趋势(数小时到数天)。

**资金分配**:80%(物理隔离子账户 1)
**工具**:现货为主 + 衍生品按需
**双向**:多空都做
**预期持仓周期**:平均 1-3 天,最长 7 天(Time Stop 底线)
**预期年触发频率**:50-150 次入场(粗略估计,待 paper 验证)

### 13.2 策略 1 入场决策树

完整入场决策按以下顺序判定。**任一步骤失败,本次入场放弃**:

```
入场决策树(策略 1)
═══════════════════════════════════════════════════

Step 1: 4H 状态判定(必须满足之一)
  ├─ Coiling(蓄能完成,等爆发)
  └─ Drifting-Charged(已蓄能,等爆发)
     
  失败状态(直接 abort):
  ├─ Drifting-Calm     (无方向)
  ├─ Surging           (已经在趋势中,不追)
  ├─ Critical          (风险过高)
  └─ Cascade           (红线)

Step 2: 状态最小停留校验
  - Coiling 必须已停留 ≥ 6 个 4H bar
  - Drifting-Charged 必须已停留 ≥ 4 个 4H bar
  - 若刚进入状态(< 最小停留),abort

Step 3: CUSUM-Mid 触发判定
  - C+_t > h_t (上行触发) → 候选方向 = LONG
  - |C-_t| > h_t (下行触发) → 候选方向 = SHORT
  - 都未触发 → abort,等下一个 4H bar

Step 4: 衍生品过滤(任一失败 abort 或降级)
  4a. funding rate 检查
      ├─ 候选 LONG + funding > 90 分位 → abort(顶部 Crowding)
      ├─ 候选 SHORT + funding < 10 分位 → abort(底部 Crowding)
      └─ funding 未极端 → 继续
  
  4b. OI 累积方向检查
      ├─ 候选 LONG + OI 持续下降 → 降级:仓位减半
      ├─ 候选 SHORT + OI 持续上升 → 降级:仓位减半
      └─ 同向 → 继续
  
  4c. liquidation 数据检查
      ├─ 过去 1h 出现大规模 liquidation 脉冲(> 30 天均值 5x)→ abort
      └─ 正常 → 继续

Step 5: 链上过滤(辅助,非阻断)
  - 大额提现持续 + 候选 LONG → 信号增强(冷储利好)
  - 大额充值持续 + 候选 LONG → 信号削弱(可能抛售)
  - 不构成 abort 条件,只调整仓位置信度

Step 6: Divergence(跨所价差)校验
  - 当前跨所价差 > 0.3% → abort(异常,等收敛)
  - 否则 → 继续

Step 7: 反推词汇增强(可选,非阻断)
  - 检查同时出现的反推词汇
  - Sweep 出现 + 同向 → 仓位置信度 +20%
  - Saturation + Coiling → 仓位置信度 +15%
  - Absorption 反向 → 仓位置信度 -30%(警告)

Step 8: 仓位计算
  base_size = 子账户 1 资金 × 20%(单笔 base 上限)
  最终仓位 = base_size × 反推词汇增强系数 × CUSUM 强度系数
  CUSUM 强度系数 = min(1.5, C+_peak / h_t) 即 [1.0, 1.5] 范围
  
Step 9: 入场执行
  - 现货为主(降低 funding 成本)
  - 若 funding 反向极端(可赚取 funding),用永续合约
  - 入场价 = 当前盘口中价 + 滑点估计
  - 滑点模型:tick 数据校准

═══════════════════════════════════════════════════
```

## 16. 阈值标定方法(4H 尺度重标定)

### 16.1 阈值的统一原则(继承 v1.0)

sel 中所有阈值(状态进入条件、CUSUM h、反推词汇分位等)遵循:

1. **滚动分位数,非固定数值**
   - "过去 30 天 90 分位"而非"σ > 0.02"
   - 原因:BTC 波动 regime 变化,固定数值会失效

2. **只用过去数据**(因果性)
   - 计算 t 时刻的阈值时,只用 t-Δ 之前的数据
   - 严禁未来数据泄漏

3. **滚动窗口长度因维度而异**
   - σ / 熵 / 价格相关:30 天
   - OI / funding 相关:60 天
   - liquidation:30 天
   - CUSUM h:策略 1 = 30 天,策略 2 = 7 天

4. **分位数选择保守**
   - 状态进入条件用 30 / 70 分位(中等敏感度)
   - Critical / Cascade 用 90 / 97 分位(罕见事件)

### 16.2 4H 尺度的重标定(v2.0 关键变化)

v1.0/v1.1 的所有阈值是**基于 1H 数据**校准的。**v2.0 改 4H 后,所有阈值需重新标定**。

⚠️ **不是简单乘 4** — 4H 上的统计量(σ / 熵 / OFI 累积)与 1H 不是简单线性关系。

**重标定步骤**(在 paper 启动前,使用历史回测数据):

```
重标定流程(paper 启动前)
═══════════════════════════════════════════════════

Step 1: 取 BTC 4H 数据 2 年(2024-01 → 2026-01)
Step 2: 计算各维度的滚动 30 天分布
  - 4H 价格 σ
  - 4H LOB 熵(从 4H 内 LOB 快照计算)
  - 4H OI 变化率
  - 4H OFI 累积(从 1min 聚合)
Step 3: 取相应分位数作为初始阈值
  - Coiling 进入:σ < 30 分位 + 熵 < 30 分位
  - Critical 进入:σ > 90 分位
  - Cascade:σ > 97 分位
Step 4: 在历史数据上跑状态机,检查触发率
  - 健康分布(目标值,占位符):
    Coiling 占 20-30% / Drifting 占 40-60% / 
    Surging 占 10-20% / Critical 占 1-5% / Cascade 占 < 1%
  - 实际触发率严重偏离目标 → 调整阈值或结构
Step 5: 锁定阈值,开始 paper trading
═══════════════════════════════════════════════════
```

### 16.3 CUSUM 阈值的特殊标定

CUSUM 的 h_t 是 **CUSUM peak 值的滚动分位数**,不是收益率分位数:

```
CUSUM-Mid 阈值标定:
  - 计算过去 30 天每个 CUSUM 重置周期的 peak C+ 值
  - 取 90 分位作为 h_t
  - 即:h_t = quantile_90(C+_peak in past 30 days)

CUSUM-Short 阈值标定:
  - 计算过去 7 天每个重置周期的 peak C+ 值
  - 取 95 分位作为 h_t

drift k 不滚动调整:
  - k = 0.5σ(σ 是 z-returns 的标准差,理论上 = 1)
  - 因为 z 已标准化,k = 0.5 是 Lopez de Prado 经典推荐
  - 不需要根据数据调整
```

⚠️ **占位符警告**:90 / 95 分位是初始猜测,paper 跑 1 个月后根据真实触发频率调整。**不要在 paper 启动前根据"直觉"调整**。

## 17. OOS 切分(Forward-Chaining)

### 17.1 为什么用 forward-chaining

传统 80/20 train/test 切分**在金融数据上有重大缺陷**:
- 假设数据 IID(BTC 显然不 IID)
- 不考虑 regime 切换
- 无法验证"未来未见过的 regime"下的表现

**Forward-chaining**(也叫 walk-forward analysis)按时间顺序滚动评估:

```
Forward-Chaining 示意
═══════════════════════════════════════════════════

数据时间轴:
[──────── Train_1 ────────][Test_1][Train_2 ────────][Test_2]...

Train_1: 2024-01 → 2024-12(12 月历史标定阈值)
Test_1:  2025-01 → 2025-03(3 月 OOS 验证)

Train_2: 2024-04 → 2025-03(滑动窗口,12 月)
Test_2:  2025-04 → 2025-06(3 月 OOS)

...继续滚动...

═══════════════════════════════════════════════════
```

### 17.2 sel v2.0 的 OOS 切分方案

**初始 OOS 验证**(paper 启动前):
- Train:2024-01 → 2025-12(24 月历史)
- Test:2026-01 → 2026-03(3 月 OOS,paper 启动前的"纸上 OOS")

**paper 期间的滚动 OOS**:
- 每月底,使用过去 12 个月数据重新标定阈值
- 下个月用新阈值跑 paper
- 比较"重新标定 vs 不变"的 PnL,判断阈值漂移

### 17.3 OOS 切分的重要纪律

按规则 #17 + 公理 5(可证伪 > 解释力):

⚠️ **绝对禁止**:
- 看 OOS 表现差 → 反向调整 IS 阈值 → 让 IS 看起来更好
- 这是经典过拟合,sel 项目零容忍
- 如果 OOS 持续表现差,直接承认假设失败,而非调参

### 案例 1:Wyckoff Spring(吸筹尾声假突破)

**实证强度**:弱

## 21. sel 对 ICT/PA 的处置原则

### 21.1 处置原则

按公理 5 + 实证强度:

**强实证(Sweep / Volume Climax / Absorption)**:
- 直接进入 sel 反推词汇
- 在策略 1/2 入场决策中作为权重因子

**中等实证(Saturation / Crowding)**:
- 进入 sel 反推词汇
- 作为辅助信号,非主驱动

**弱实证或文献空白(Wyckoff / FVG / Order Block)**:
- observation-only
- paper 期间收集数据
- 3 月后基于实际数据决定是否启用

### 21.2 不被 sel 收录的 PA/ICT 概念

以下 PA/ICT 概念虽然流行,但 sel v2.0 **不收录**:

- **裸 K 线形态**(Doji / Hammer / Engulfing 等):无严肃实证支持
- **Fibonacci 比率**:在 BTC 上无统计显著性
- **Elliott Wave**:主观性太强,不可量化
- **Gann angles / 时间循环**:无任何实证支持
- **Harmonic Patterns**(Bat / Butterfly 等):无严肃实证

⚠️ Wiki 在 paper trading 期间**不应**因为某周表现差就考虑添加这些概念。这违反 sel 项目纪律。

## 23. v2.0 调研结果汇总

v2.0 在 v1.1 基础上做了**大规模文献调研**(2026-04-29),核心调研发现:

### 23.1 1H 时间尺度的实证缺陷

**关键文献**:Bieganowski & Slepaczuk 2026(arxiv 2602.00776)
**关键发现**:BTC 60-300 min 是噪声敏感区,信噪比最差
**对 sel 影响**:1H(在噪声区中段)升级到 4H(在噪声区出口)

### 23.2 HMM regime detection 主流尺度

**关键文献**:Machimbo 2025 / TVTP-MS-HAR 2025 / 多篇
**关键发现**:BTC HMM regime detection 主流用 4H 或 daily,1H 较少
**对 sel 影响**:支持 4H 主时间锚点决定

### 23.3 Wyckoff 在 BTC 上的真实尺度

**关键文献**:Wyckoff Analytics / Altrady 2025(实战派,非同行评议)
**关键发现**:BTC 上 Wyckoff 阶段在 4H 上最清晰
**对 sel 影响**:支持 4H 决定;但 Wyckoff 派生词汇仍 observation-only(无严肃量化文献)

### 23.4 OFI / Hawkes / 跨所信号的真实尺度

**关键文献**:Cont 2010 / Lu & Abergel 2018 / Bishop 2022 / Decisions in Economics 2026
**关键发现**:
- OFI 在 10 秒级有效
- Hawkes 在毫秒到秒级有效
- 跨所价格领先在 500ms 级有效
**对 sel 影响**:这些信号无法直接用 4H 状态机,但可以
- 通过 CUSUM-Short 在事件流中捕获(策略 2)
- 通过 15min 聚合特征作为 4H 状态机的辅助输入

### 23.5 Information-driven bars 的统计性质优势

**关键文献**:Lopez de Prado 2018 + Grądzki et al 2025
**关键发现**:
- 时间 bar 的统计性质(分布、自相关、平稳性)在 BTC 上严重有偏
- Volume / Dollar / CUSUM bar 显著更接近正态分布
**对 sel 影响**:CUSUM event-driven 不仅是"信号采集方法",也是"统计推断的更可靠基础"

### 23.6 衍生品 cycle 的真实结构

**关键文献**:XT Exchange 2026 + 2025-11 cascade 实战分析
**关键发现**:BTC 衍生品 cycle = OI 增长 → funding 极端 → catalyst → liquidation cascade → reset
**对 sel 影响**:
- 衍生品维度从 v1.0 的"Crowding 单一词汇"升级到"sel 第二支柱"
- 在每个状态中显式纳入衍生品累积变化作为转换条件

### 23.7 post-ETF 时代 BTC 市场结构变化

**关键文献**:Outlook 2026 / 2025-11 Ethena 干扰事件
**关键发现**:
- BTC 市场结构 2024+ 进入 ETF 时代,流动性碎片化加剧
- Ethena 等基差套利协议长期压低 funding,使"funding = 散户拥挤"解释失效
**对 sel 影响**:
- Crowding 词汇增加 post-ETF 警告(第 7.4 节)
- 跨所 Divergence 词汇升级为独立信号(第 7.5 节)

### 23.8 CUSUM event-driven 在 BTC 上的实证表现

**关键文献**:Alexdemachev 2026 + Grądzki 2025
**关键发现**:
- 25 个月 BTC paper trading:+324% PnL,但 t-stat=1.03,p=0.157
- **未达统计显著性**,但经济上有迹象
**对 sel 影响**:
- 策略 2 的回报预期必须保守
- 策略 2 是研究 + 数据收集目的,不是高确信度盈利

## 24. 已知缺陷与盲区

按规则 #11(诚实到不舒服),v2.0 的已知缺陷必须显式列出:

### 24.1 结构性缺陷

#### 缺陷 1:Cascade 样本严重不足
- 1 年 Cascade 触发估计 5-30 次
- 任何 Cascade 后续行为的统计推断**低置信度**

- 6 状态(含 Drifting-Calm/Charged 细分)
- 主流 HMM 文献用 3-4 状态
- 风险:Drifting-Calm/Charged 重叠率高时,细分无意义
- 缓解:paper 跑 3 月后评估重叠率,> 50% 则合并

#### 缺陷 3:反推词汇大部分弱实证
- 7 个反推词汇中,4 个是中等或弱实证(Imprinting / Wyckoff 派生 / Saturation 部分)
- 风险:这些词汇在 paper 中可能噪声大于信号

#### 缺陷 4:策略 2 的统计显著性问题
- Alexdemachev 2026 实证 p=0.157,未达显著
- 即使加上 sel 反推词汇增强,显著性是否提升未知
- 缓解:策略 2 的 PnL 预期必须保守,且作为"次要"策略

#### 缺陷 5:跨策略协调的简化代价
- N2 决定:同向独立 + 反向独立
- 风险:反向对冲发生频繁时,手续费 + 滑点累积成本高

### 24.3 哲学层面盲区

#### 盲区 1:sel 假设的整体可证伪性
- 单个词汇/状态可证伪
- 但"sel 整体"的可证伪条件未明
- 即:即使每个状态都"工作",整体策略仍可能不盈利

- 1 年时间不足以跨 BTC 完整周期(2-4 年)
- Helixa 和 Selene 风格差异极大 — 难判定是"哲学差异"还是"实施细节差异"
- 真正的对照需要 **3+ 年多市场** — 在 sel 项目当前阶段不可能

**结论**:Helixa vs Selene 对照是**研究迭代的方向参考**,不是"哪个是真理"的最终判定。

## 27. decision_trail schema

### 27.1 表结构(TimescaleDB)

```sql
CREATE TABLE decision_trail (
    id              UUID PRIMARY KEY DEFAULT uuidv7(),
    timestamp       TIMESTAMPTZ NOT NULL,
    decision_type   TEXT NOT NULL,  -- 'parameter_change' / 'strategy_skip' / 'manual_override' / etc
    
    -- 触发上下文
    trigger_source  TEXT NOT NULL,  -- 'weekly_report' / 'manual' / 'auto_alert' / 'crash_recovery'
    week_number     TEXT,           -- YYYY-WW(如适用)
    
    -- 决策内容
    target_component TEXT NOT NULL, -- 'strategy_1_cusum' / 'strategy_2_cusum' / 'state_machine_threshold' / etc
    parameter_name  TEXT,
    old_value       JSONB,
    new_value       JSONB,
    
    -- 决策理由(双方各写一栏)
    claude_suggestion   TEXT,        -- Claude 的建议(可空)
    wiki_decision       TEXT NOT NULL, -- Wiki 的最终决策(必填)
    decision_basis      TEXT,        -- 决策依据(数据 / 文献 / 直觉 / 等)
    
    -- 元信息
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    created_by      TEXT NOT NULL,  -- 'wiki' / 'claude' / 'cc'
    
    -- 复盘字段(后续填)
    revisited_at    TIMESTAMPTZ,    -- 后续何时被回顾
    revisit_outcome TEXT             -- 'good' / 'bad' / 'neutral'
);

CREATE INDEX idx_decision_trail_timestamp ON decision_trail (timestamp DESC);
CREATE INDEX idx_decision_trail_component ON decision_trail (target_component, timestamp DESC);
SELECT create_hypertable('decision_trail', 'timestamp');
```

### 27.2 decision_trail 写入权限

按 N5-c:
- **Claude 写入权限**:仅 `claude_suggestion` 字段
- **Wiki 写入权限**:`wiki_decision` 字段(必填)+ 其他字段
- **CC 写入权限**:自动写入(运行时事件,如 strategy_skip 因 cascade 触发)

### 27.3 复盘机制

每月底,从 decision_trail 抽取过去 30 天所有决策,做复盘:

- **good**:决策后该参数表现改善
- **bad**:决策后表现恶化
- **neutral**:无显著差异

⚠️ 复盘是 **Claude 的关键学习数据** — 让我能看到自己过去给的建议是否真的有用。

## 28. 调参纪律

### 28.1 调参允许的范围

允许调参:
- ✅ CUSUM 阈值 h_t 的分位数(如从 90 改为 92 分位)
- ✅ CUSUM 累积窗口(如策略 1 从 1h 改为 90min)
- ✅ 状态进入/离开的分位数阈值
- ✅ 反推词汇的增强系数
- ✅ 仓位 base_size 比例

### 28.2 调参禁止的范围

禁止调参(架构层面冻结):
- ❌ 主时间锚点(4H 不可改为 1H 或 8H)
- ❌ 双策略架构(不可合并为单策略,也不可拆为三策略)
- ❌ 子账户资金分配(80/20 paper 期间锁定)
- ❌ 状态数量(6 状态不可增减)
- ❌ 风控红线(Cascade 立即清仓 / 浮亏 -3%/-2% / Time Stop)
- ❌ 公理 1-5

### 28.3 调参的频率约束

- **paper 第一个月**:不允许调参(让数据说话)
- **paper 第二个月起**:每月最多调一次(随月度复盘)
- **重大异常事件后**:可临时调参(如 CUSUM 阈值明显错位),需 Wiki + Claude 双重确认
- **连续两次调参未带来改善**:停止调参 1 个月,反思架构是否真的有效

### 28.4 调参的复盘要求

每次调参必须:
1. 写入 decision_trail
2. 在下个月复盘
3. 记录"是否实际改善"
4. 如果连续 3 次调参无改善,**整个 sel 项目进入停摆评估**

⚠️ 这是 sel 项目的"自毁开关":如果架构真的不工作,要愿意承认。

```sql
    id              UUID PRIMARY KEY DEFAULT uuidv7(),
    strategy        TEXT NOT NULL,
    param_name      TEXT NOT NULL,
    param_value     JSONB NOT NULL,
    valid_from      TIMESTAMPTZ NOT NULL,
    valid_to        TIMESTAMPTZ,             -- 当前生效则为 NULL

    created_at      TIMESTAMPTZ DEFAULT NOW()

CREATE INDEX idx_strategy_params_active ON strategy_params (strategy, param_name) 
    WHERE valid_to IS NULL;
```

## 附录 C:可证伪假设速查

按公理 5,sel v2.0 的核心假设及可证伪条件:

```
可证伪假设清单
═══════════════════════════════════════════════════

H1: 4H 状态机能识别有意义的市场 regime
  可证伪条件:
    - 状态触发率严重偏离健康分布(目标占位符)
    - 状态切换无法预测后续行为(如 Surging 进入后未来 24h 与随机无差)

H2: CUSUM-Mid 触发 + 状态过滤 = 策略 1 有正期望
  可证伪条件:
    - paper 6 月后,策略 1 累计 PnL 显著为负
    - 或 Sharpe < 0(账户级)

H3: CUSUM-Short + 反推词汇 = 策略 2 有正期望
  可证伪条件:
    - paper 6 月后,策略 2 累计 PnL 显著为负
    - 或 t-stat < 1(类似 Alexdemachev 2026 的水平,即策略 2 没比纯 CUSUM 更好)

H4: 反推词汇增强 vs 不增强 有可量化差异
  可证伪条件:
    - 关闭反推词汇增强,策略 2 表现无显著变化
    - 这表明反推词汇是 noise,不是 signal

H5: 衍生品过滤(funding/OI)真的过滤掉差入场
  可证伪条件:
    - 比较"被过滤掉的入场"和"通过过滤的入场",前者期望不显著差于后者
    - 这表明过滤是无意义的

H6: Cascade 立即清仓比"持有等反弹"更优
  可证伪条件:
    - Cascade 后 24h 平均反弹 > clearing 时的损失
    - 此条件由于 Cascade 样本不足,难以快速证伪/证实

H7: 物理隔离子账户 vs 共享账户在 Cascade 期间真的有保护作用
  可证伪条件:
    - 模拟实验显示共享账户在 paper 中也未被 Cascade 拖累
    - 注:此条件无法在 v2.0 paper 中直接验证(因为已选物理隔离)

═══════════════════════════════════════════════════
```

⚠️ 每条假设的可证伪条件**应在 paper 启动前明确写入测试用例**,paper 期间持续验证。
